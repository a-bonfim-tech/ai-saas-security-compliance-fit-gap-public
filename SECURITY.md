# Security Policy

## Supported Versions

Security fixes are maintained on the current default branch. Tagged releases are portfolio snapshots and are not implicitly supported unless the repository explicitly marks them as maintained.

## Reporting a Vulnerability

This repository is a cybersecurity engineering and portfolio project.

If you identify a security issue in the repository, please do not open a public issue containing sensitive details.

Instead, contact the repository owner privately through the communication channel listed in the GitHub profile.

## Scope

This policy applies to:

- Example scripts
- Configuration files
- Documentation
- Sample evidence files
- Control mapping logic

## Out of Scope

The following are out of scope:

- Legal compliance opinions
- Formal audit conclusions
- Certification readiness claims
- Attacks against third-party services
- Social engineering
- Denial-of-service testing

## Responsible Disclosure

Please include:

- A clear description of the issue
- Steps to reproduce
- Potential impact
- Suggested remediation, if available

## Expected Response Process

The maintainer will privately acknowledge and triage reports when access to the reporting channel is available, preserve sensitive details, validate impact, and coordinate remediation and disclosure as appropriate. This repository does not promise a response or remediation SLA.

Do not publish exploit details, credentials, personal data or other sensitive evidence in a public issue. Never test against third-party or production systems without explicit authorization.
