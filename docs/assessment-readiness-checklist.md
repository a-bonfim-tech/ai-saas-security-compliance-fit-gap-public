# Assessment Readiness Checklist

## Technical Readiness

- [ ] I can explain the repository purpose in English.
- [ ] I can run `pnpm typecheck`.
- [ ] I can run `pnpm analyze`.
- [ ] I can run `pnpm evidence:refresh-all`.
- [ ] I can explain the control catalog.
- [ ] I can explain the evidence register.
- [ ] I can explain the generated Markdown, JSON and CSV reports.
- [ ] I can explain how evidence supports compliance conclusions.

## Framework Readiness

- [ ] I can explain NIST CSF 2.0 at a high level.
- [ ] I can explain ISO 27001 as an ISMS standard.
- [ ] I can explain SOC 2 in a SaaS context.
- [ ] I can explain GDPR relevance to SaaS and AI.
- [ ] I can explain EU AI Act relevance to AI systems.
- [ ] I can explain OWASP relevance to application and LLM security.

## SaaS Security Readiness

- [ ] I can review GitHub branch protection.
- [ ] I can review Dependabot and CodeQL configuration.
- [ ] I can identify basic secure SDLC evidence.
- [ ] I can discuss authentication and authorization risks.
- [ ] I can discuss secrets management.
- [ ] I can discuss cloud IAM, logging, encryption and backups.
- [ ] I can discuss PostgreSQL security basics.

## AI Governance Readiness

- [ ] I can document an AI system purpose.
- [ ] I can map AI data flows.
- [ ] I can identify prompt injection risk.
- [ ] I can identify sensitive data leakage risk.
- [ ] I can discuss human oversight.
- [ ] I can review AI vendor risk.
- [ ] I can discuss transparency obligations.

## Professional Readiness

- [ ] I can explain the project as security assessment preparation.
- [ ] I can describe the value to a B2B SaaS company.
- [ ] I can explain how the project could evolve into an internal compliance automation tool.
- [ ] I can connect findings to remediation priorities.
- [ ] I can communicate limitations clearly.
